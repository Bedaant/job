## 1. Which ATS expose a fetchable question schema and accept third-party submission?

### Takeaway
Greenhouse, SmartRecruiters, Workable and (per third-party sources) Ashby expose public/semi-public posting data; Greenhouse exposes questions on a public GET. Submission via API is gated everywhere: Greenhouse needs an employer-issued Job Board API key (Basic auth), Lever needs an employer Super Admin key and does NOT expose custom questions, SmartRecruiters Application API is OAuth/partner-gated. A candidate-side SaaS cannot generally submit via official API without per-employer keys or partner deals. Best use: read schemas via public GETs, then fill the real DOM form in the user's browser.

### Cited Findings
- Greenhouse Job Board API: only the submit endpoint (POST .../jobs/{id}) requires Basic Auth; read endpoints are open. — [Greenhouse Job Board docs via search](https://developers.greenhouse.io/job-board) and [Greenhouse support](https://support.greenhouse.io/hc/en-us/articles/10568627186203) (snippet-level; pages not opened)
- Greenhouse: passing the `questions` parameter on GET job returns custom questions and EEOC compliance questions; `demographic_questions` appears only if the org has Greenhouse Inclusion and demographic questions are enabled on the post. — [Greenhouse Job Board](https://developers.greenhouse.io/job-board) (snippet-level)
- Greenhouse POST auth is Base64 Job Board API key (from third-party directory, unconfirmed against official docs). — [Knit](https://getknit.dev/blog/greenhouse-api)
- A third-party skill guide claims Greenhouse's submit handler also checks a reCAPTCHA Enterprise token and client fingerprint, so pure API submit isn't viable. Secondary source, unverified. — [browse.sh](https://www.browse.sh/skills/greenhouse.com/apply-to-jobs-dsmal1)
- Lever Postings API apply: `POST /v0/postings/SITE/POSTING-ID?key=APIKEY`; JSON or multipart (resume only in multipart); `name` and `email` required; key generated by a Super Admin in integrations settings; HTTP 429 above 2 application POSTs/sec per custom job site; API does not expose custom questions built into postings; EEO fields not mentioned. — [lever/postings-api](https://github.com/lever/postings-api) (verified by fetch)
- Ashby: public read endpoint api.ashbyhq.com/posting-api/job-board/{name}?includeCompensation=true, no auth; one scraper says it does not submit applications. Official docs unopened; no confirmation of a public application-submit endpoint or form-schema endpoint. — [Apify Ashby actors](https://apify.com/istenotools/ashby-jobs-api) (third-party)
- SmartRecruiters Application API: GET /postings/:uuid/configuration (screening questions, privacy policies), POST /postings/:uuid/candidates (create application), GET .../status; all protected, OAuth scope candidate_applications_manage; listed under Marketplace/partner APIs; diversity questions must be shown last with a "Confidential Diversity Questions" notice. Posting API is API-key, read-only, public data available unauthenticated. — [SmartRecruiters Application API](https://developers.smartrecruiters.com/docs/application-api), [Posting API](https://developers.smartrecruiters.com/docs/posting-api)
- Workable: API v3; limit 10 requests/10 seconds (429); questions endpoint /jobs/:shortcode/questions; candidate creation POST /spi/v3/jobs/{shortcode}/candidates requires w_candidates scope (third-party; employer-token based, no documented candidate-side apply). — [Workable v3](https://workable.readme.io/docs/whats-new-in-v3), [Knit](https://getknit.dev/blog/get-all-candidates-for-a-job-from-workable-api-d9oljb.md)
- Indeed Apply: ATS receives applications via HTTPS POST (`indeed-apply-postUrl`) with JSON, signed with X-Indeed-Signature, screener questions in a defined JSON; this is an employer/ATS-side receiver, integration ~6 weeks incl. review. Not a candidate-side API. — [Indeed docs](https://docs.indeed.com/indeed-apply/ats), [Job Sync](https://docs.indeed.com/job-sync-api/integrate-with-job-sync-api)
- Zoho Recruit: employer-configurable application form with mandatory/optional fields, embeddable; API OAuth is per data-centre region; community says Publish/Keep_on_Career_Site fields read-only via API. — [Zoho Recruit](https://www.zoho.com/recruit/career-site.html), [Zoho community](https://help.zoho.com/portal/pt/community/topic/option-to-automatically-publish-job-openings-to-the-career-website-via-api-or-workflow-16-3-2026?page=2)
- Workday: no official candidate-facing API found. Only evidence of DOM attributes: Nexthink guide lists data-automation-id, data-uxi-element-id, data-uxi-widget-type as stable selector attributes for Workday. — [Nexthink](https://docs.nexthink.com/platform/user-guide/adopt/guide-creation-and-management-from-nexthink-applications/configuring-adoption-settings/use-case-element-selectors-for-workday)

### Inferences
- Greenhouse is the best candidate for a "read schema via API, fill real form" path because questions GET is public; submission should remain via the actual hosted form with user clicking Submit (reCAPTCHA, API-key gate).
- Lever's lack of custom-question exposure means schema must come from the hosted apply page DOM (jobs.lever.co/.../apply) regardless of API.
- Employer-side keys mean official apply APIs are structurally unavailable to a candidate-side product; ApplyScout's extension model sidesteps this.

### Gaps
- Not researched: iCIMS, Taleo/Oracle, SuccessFactors, Recruitee, Breezy, Teamtailor, JazzHR, BambooHR, Workday Recruiting API, Keka Hire, Darwinbox, Freshteam, Naukri RMS, Instahyre, HireLakhs, PeopleStrong, HR Open Standards, LinkedIn Apply Connect, schema.org JobPosting (note: JobPosting has no question schema; inference only), Google for Jobs.
- Greenhouse exact POST field names, rate limits and any ToS on third-party submission; Ashby official docs; Lever hCaptcha status.

## 2. Unified APIs (Merge, Kombo, Unified.to, Apideck, Finch)

### Takeaway
Unified ATS APIs are employer-authorised (end-customer links their ATS account), so they serve employer-side/HR-tech products, not candidate-side apply. Merge does support POST /Applications, but only inside a linked customer's ATS.

### Cited Findings
- Merge: "source candidates" use case uses POST /Applications (and POST /Candidate if needed) in the customer's ATS; screening answers can be a submodel. — [Merge docs](https://docs.merge.dev/merge-unified/use-cases/source-candidates)
- Merge pricing (competitor-reported, unverified): Launch tier first 3 linked accounts free, then $650/mo up to 10 production linked accounts, $65/mo per extra; higher tiers contract-based. 2021 changelog showed older per-candidate pricing (stale). — [Nango](https://nango.dev/blog/merge-pricing), [Apideck](https://apideck.com/blog/merge-and-apideck-pricing-compared), [Merge 2021](https://www.merge.dev/changelog/week-4-august-2021)
- Kombo: pricing not found officially; a comparison table shows $650/mo up to 10 linked accounts (attribution unclear). Apideck: pay per consumer, lists Greenhouse and Lever. — [Apideck](https://apideck.com/alternatives/kombo-dev)

### Inferences
- A linked-account model requires each employer to connect; irrelevant to a job seeker applying to arbitrary postings. Not recommended.

### Gaps
- Candidate-side submission support in Kombo, Unified.to, Apideck, Finch not verified; Finch is HRIS/payroll so likely irrelevant (inference).

## 3. Shared DOM patterns, open-source autofill, datasets

### Takeaway
Many open-source extensions special-case Greenhouse/Lever/Workday; Workday needs data-automation-id selectors; no job-application-specific public dataset found.

### Cited Findings
- Autofill Jobs (Vue, Greenhouse, Lever, Dover, Workday); notes Greenhouse uses React components so fill method differs from Lever. — [andrewmillercode/Autofill-Jobs](https://github.com/andrewmillercode/Autofill-Jobs)
- Kumquat/Kaleidoscope (Taleo, Workday, Lever, Greenhouse), no longer actively supported. — [Chrome Web Store](https://chrome.google.com/webstore/detail/kumquat/mkjkimankkfhefaabddppkhbobffaadp?hl=en-US), repo rpeng220/kaleidoscope
- Autograph: Free ATS Autofill, GPL-3.0, claims Workday, Greenhouse, Lever, Ashby + 17 others (repo not linked in results). JobAppFiller open source; changelog mentions Greenhouse multi-select limitations. — [Autograph](https://chromewebstore.google.com/detail/diglnccklgegdlgfnoebadmoglnkcfho), [JobAppFiller scan](https://extensionauditor.com/scan/autofill-job-applications-jobappfiller-gdballabidaicjchgomokfmalodbkeoc)
- Workday: Autofill Job Applications changelog shows fixes for year input, field of study, yes/no radios; vendor notes Workday still needs manual review after resume parse. — [chromeboard](https://www.chromeboard.com/extension/autofill-job-applications-gdballabidaicjchgomokfmalodbkeoc), [JobWizard](https://jobwizard.ai/blog/why-workday-makes-you-re-enter-your-resume-after-uploading-it)

### Gaps
- Actual selector code not inspected (licences: check GPL-3.0 contamination before reuse). No dataset of real application forms found.

## 4. Form-understanding approaches and accuracy

### Takeaway
No job-application-specific benchmark found; closest are FormFactory and FormGym, which show agents are weak end to end.

### Cited Findings
- FormGym: 432 fields/55 documents; VLA baselines <1% accuracy; GUI agents 10.6-68.0%; (PDF-form focus, EACL 2026). — [arXiv 2506.14079](https://arxiv.org/abs/2506.14079v2)
- FormFactory: 25 web forms, 1,250 instances, 13,800 field-value pairs; tested GPT-4o, Gemini 2.5 Pro, Claude Sonnet 3.7; metrics click and value accuracy; headline numbers not retrieved. — [arXiv 2506.01520](https://arxiv.org/pdf/2506.01520)

### Inferences (unsourced engineering judgement)
- Recommended stack: ATS adapter / schema from API or DOM -> rule/synonym + embedding match to profile -> small LLM only for ambiguous/free-text -> constrained choice among the form's own options -> confidence threshold, below which field is left for user. Cost per form not measured; no published numbers found.

### Gaps
- Cost per form with Claude/NIM, embedding-vs-rules accuracy, open-source implementations.

## 5. EEO / demographic fields

### Takeaway
Detectable on Greenhouse via explicit structures; default should be leave blank or "decline to self-identify".

### Cited Findings
- Greenhouse returns EEOC compliance questions and demographic_questions as separate objects from GET job with questions. — [Greenhouse](https://developers.greenhouse.io/job-board) (snippet)
- SmartRecruiters requires diversity questions shown last under a confidential notice, giving a stable detection cue. — [SmartRecruiters](https://developers.smartrecruiters.com/docs/application-api)
- US forms are voluntary with a decline option; refusing has no adverse treatment per sample forms. — [Jones Center form](https://www.jonesctr.org/wp-content/uploads/2022/03/EEOC_Census-form-Self-ID-for-applicants.pdf)

### Inferences
- Detection: schema-level flags (Greenhouse, SmartRecruiters), plus keyword classifier (race, ethnicity, gender, veteran, disability, caste/category, PwD, religion) on labels; auto-select "decline" only if present, else leave blank; require user choice for any India category/PwD/religion field. No source on India-specific ATS fields.

### Gaps
- Keka, Darwinbox, Zoho India category/PwD field handling not found.

## 6. Verdict (largely inference)

- Build first: Greenhouse (public question GET + stable hosted DOM), Lever (hosted DOM, common among startups), Workday (data-automation-id; hardest, ubiquitous in enterprises/GCCs), Ashby (public posting API). Then Indian: Zoho Recruit (large SME share per vendor blogs), Keka, Darwinbox (HRMS-embedded; likely no public candidate API; need DOM adapters) — India ATS market share figures not found; only vendor blogs ([PitchNHire](https://www.pitchnhire.com/blog/Top-ATS-Companies-in-India-2025), [IMARC](https://www.imarcgroup.com/india-applicant-tracking-system-market)).
- Do not pursue official apply APIs or unified APIs for submission; employer-key gated. Keep generic LLM agent fallback for custom career sites, Naukri/Instahyre native flows, and unknown ATS.

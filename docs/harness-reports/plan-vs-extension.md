## Verdict, first run (2026-09-29): no overall gain; the plan stays on for Greenhouse only

Required fields filled on 13 postings with both runs: 62 without a plan, 60 with one.

- Demographic violations 0/0. Every run had the guard on, nothing was submitted, and the 2 submit attempts are Lever's own page script,
  which the guard blocked.

**Decision:** `formplans.ROUTED_ATS = {"greenhouse"}`. Only Greenhouse plans reach map-fields, and the hourly sweep
plans only Greenhouse jobs. Lever and Ashby keep today's filler. The CLI still plans all three for measurement.

**Found and fixed along the way:**
- The Zoox "How did you hear?" checkbox labelled "LinkedIn" was ticked in the plan run. The plan did not fill it:
  map-fields never routes a profile value into a checkbox. The LLM path ticked it in one run and not the other.
  That risk existed before this work, and it is logged in WORKLOG. The plan's label matcher also no longer matches a radio/checkbox
  *option* label, only its question.
- Robinhood's plan failed with a Neon "connection closed" error. The session held its connection while the planner
  ran for minutes. `plan_job` now commits before starting the planner.
- Notion's plan failed because NIM was overloaded (3 attempts). That is the provider, not the code.

# Build the filler, borrow the plumbing

**Verdict: hybrid, weighted heavily toward build.** ApplyScout should keep and extend its own Chrome MV3 filler: a deterministic ATS adapter and answer-bank mapper that fills first, with a text-only LLM call (NVIDIA NIM or Claude) for the few leftover fields. Buy only commodity pieces: MIT/Apache-2.0 code for DOM distillation and test harnesses, and a cheap cloud or local browser for nightly regression. No vendor was found that sells a candidate-side autofill API or white-label mapper. The leaders (Simplify, Careerflow) are end-user subscriptions, and employer-side ATS submit APIs need per-employer keys a job-seeker SaaS cannot get. Full autonomous browser agents are the wrong tool for the production flow. Their best independent scores on live-web benchmarks sit around 40-60%, and no ATS-specific benchmark exists. Server-side agents also mean storing user credentials, running from datacenter IPs and paying per-application COGS, while the user's own logged-in Chrome avoids all three. Treat every price, date and benchmark below as a search-summary figure unless marked verified. The licence labels were verified by cloning the repos: Page Agent (MIT), Nanobrowser (Apache-2.0), Browser Use (MIT), Stagehand (MIT), Skyvern (AGPL-3.0) and WebBrain (GPL-3.0). The researchers' own fetches of vendor sites, Chrome Web Store, official ATS docs and arXiv failed, so the re-check list at the end is long.

## Four product families, one that fits

The market splits cleanly. **In-page and extension-side tools** run in the user's own browser. Alibaba's Page Agent is MIT, has about 29.4k stars, reads a text DOM with no screenshots, and accepts any OpenAI-compatible endpoint, including ApplyScout's own backend or NIM. Its newest release in the notes is v1.12.4, dated 6 Sep with no year shown, so about five weeks old if that is 2026 ([GitHub](https://github.com/alibaba/page-agent), [releases](https://github.com/alibaba/page-agent/releases)). Nanobrowser is Apache-2.0 with about 14.1k stars and a side-panel planner/navigator design. Its v0.2.0 is dated 2 Oct, but the year is again inferred, and its release cadence is roughly quarterly ([GitHub](https://github.com/nanobrowser/nanobrowser)). WebBrain is very active, with commits on 8-11 Oct 2026, and it has plan approval and per-site permission prompts, but it is GPL-3.0-or-later ([GitHub](https://github.com/webbrain-one/webbrain)). Because ApplyScout ships its extension to users, embedding GPL code would obligate it to release the extension's source. That is the "distribution" trigger, and it is the notes' inference rather than something tested in court, so WebBrain is "read the design, never copy code". Claude in Chrome is Anthropic's own closed-source extension on paid Claude plans only. It cannot be embedded or pointed at ApplyScout's backend ([support](https://support.claude.com/en/articles/12902446-claude-in-chrome-permissions-guide)).

**Server-side agents and cloud browsers** are Browser Use (MIT, about 117.6k stars), Stagehand (MIT, about 25.6k stars, act/observe/extract), Skyvern (AGPL-3.0, about 23.2k stars) and hosted browsers such as Browserbase, Steel, Hyperbrowser and Amazon Nova Act ([Skyvern](https://github.com/Skyvern-AI/skyvern), [Browser Use](https://github.com/browser-use/browser-use), [Stagehand](https://github.com/browserbase/stagehand)). Skyvern also keeps anti-bot, proxy and CAPTCHA tooling in its paid cloud only, so the open core is weaker for exactly the hard cases. **Commercial autofill and auto-apply products** split into human-in-the-loop autofill (Simplify Copilot, Careerflow, JobWizard) and volume auto-apply (LazyApply, Sonara, JobCopilot, LoopCV, and India's ApplyAI Pro, Fillix and BlinkJob). **ATS-specific APIs** are readable but not writable by a candidate-side product. Greenhouse's public GET returns custom and EEOC questions when the `questions` parameter is passed. Its submit endpoint needs an employer-issued Job Board API key, and one secondary source says it also checks a reCAPTCHA Enterprise token ([Greenhouse via search](https://developers.greenhouse.io/job-board), [browse.sh](https://www.browse.sh/skills/greenhouse.com/apply-to-jobs-dsmal1)). Lever's apply endpoint needs a Super Admin key and, in the verified README, does not expose custom questions ([lever/postings-api](https://github.com/lever/postings-api)). SmartRecruiters' Application API is OAuth/partner-gated ([docs](https://developers.smartrecruiters.com/docs/application-api)). Unified-API vendors such as Merge work only inside an employer-linked ATS account and start around $650/month (competitor-reported), so they are irrelevant to a job seeker applying anywhere ([Nango](https://nango.dev/blog/merge-pricing)). The one useful ATS API trick is reading schemas through public GETs (Greenhouse, SmartRecruiters, Ashby's posting feed per a third-party source) and then filling the real hosted form in the user's browser.

## Reliability evidence supports "deterministic first, LLM for the residue"

The benchmark picture is noisy enough that no single number should drive a decision. On Online-Mind2Web, the original human-evaluated study put Operator near **61%** ([arXiv 2504.01382](https://arxiv.org/html/2504.01382v4)). The Princeton HAL automatic-judge board had the top entry at **42.3%** (GPT-5 medium) as of a 2026-05-27 snapshot, with Browser-Use plus Claude 3.7 at 39.3% ([benchmarklist HAL mirror](https://benchmarklist.com/benchmarks/hal_online_mind2web/)). Yutori's own vendor-hosted board lists entries at about **97%** ([Yutori](https://yutori.com/leaderboards.md)). These disagree by more than 50 points because of judge, scaffold and who runs the evaluation, and the notes do not resolve it. The honest reading is that headline scores say little about multi-page ATS wizards. OSWorld-Verified is near saturation, with the top eight spanning about six points, and WebVoyager figures from Browser Use (89.1%) and Skyvern (85.85%) are self-reported ([BenchLM](https://www.benchlm.ai/benchmarks/osworld-verified), [Skyvern blog](https://www.skyvern.com/blog/skyvern-2-0-webvoyager-benchmark-results/)). Web Bench, which includes form-filling tasks, ranks Skyvern 2.0 at 64.4% and browser-use at 43.9%. The Y Combinator launch text says agents struggle most with authentication, form filling and file downloads ([benchmarklist](https://benchmarklist.com/benchmarks/webbench_ai/), [YC](https://www.ycombinator.com/launches/NdK-web-bench-a-new-way-to-compare-ai-browser-agents)).

The only form-specific web benchmark, FormFactory, reported that no mid-2025 multimodal model exceeded **5%** whole-form accuracy ([arXiv 2506.01520](https://arxiv.org/pdf/2506.01520)). That is a synthetic suite with strict scoring and older models, so it shows that whole-form exact correctness is hard, not what a 2026 model would score. No independent ATS benchmark (Workday, Greenhouse, Lever, iCIMS) was found. The nearest evidence is a blog test of Simplify across 23 applications, reporting about 90% Greenhouse, 85% Lever, 70% Workday, 50% iCIMS and 40% Taleo, from a vendor-affiliated source with unknown method ([AutoApplier](https://www.autoapplier.com/blog/simplify-copilot)). JobWizard's "90%+ Workday" claim is unpublished marketing. ApplyScout's own per-ATS fill rate will be more informative than any of these.

Cost and token evidence points the same way. Blog estimates put Browser Use around $0.07 per 10-step task, Stagehand $0.01-0.06 plus session fees, and Skyvern cloud about $0.50 ([aicoolies](https://aicoolies.com/reviews/skyvern-review)). Browser Use cloud pricing is internally inconsistent: sessions at $0.02/hr on one page and $0.06/hr in docs. A per-application agent loop is therefore a recurring cost of roughly Rs 6-45 in compute alone, before LLM tokens. A one-shot structured-fill call over a compact field list costs far less, though no per-form figure was measured anywhere. Fabrication evidence is thin but directionally clear. A preprint on 25 synthetic resumes found undefended baselines producing 2.5-5.4 detected hallucinations each, cut to about 0.04-0.24 with layered defences ([arXiv 2607.01457](https://arxiv.org/pdf/2607.01457)). A second hiring-pipeline study reported invented contact details, but its arXiv ID looks anomalous and should be verified. Both support a verified fact store, constrained choice among the form's own options, and abstain-and-ask. Prompt injection argues for the same shape: vendors report single-digit or near-zero adaptive attack success for the newest models, but OpenAI says the problem may never be fully solved ([Anthropic](https://www.anthropic.com/research/prompt-injection-defenses), [The Decoder](https://the-decoder.com/openai-admits-prompt-injection-may-never-be-fully-solved-casting-doubt-on-the-agentic-ai-vision/)). Job-description text is hostile input. The model should see labels and options as data and return only an enum value or an abstain, with no click, navigate or submit authority.

## Legal and platform risk decides where to automate

Licence risk is manageable if ApplyScout stays on MIT and Apache-2.0 code with notices retained. Page Agent's own README says it derives its DOM processing from browser-use, so version pinning and notice files matter ([GitHub](https://github.com/alibaba/page-agent)). Skyvern's AGPL network clause applies when you modify the program and let users interact with it over a network. Importing it into the FastAPI backend would create a combined work. Whether an extension talking to an unmodified AGPL service counts is untested, so the legal notes advise keeping it out of the product path ([AGPL summary](https://thebuild.com/blog/the-agpl-radioactive-by-design/), secondary source).

ToS risk is the bigger exposure and splits by site. LinkedIn explicitly prohibits third-party software and browser extensions that automate or alter its site, citing User Agreement s.8.2, and has litigated against scrapers such as Proxycurl ([LinkedIn Help](https://www.linkedin.com/help/linkedin/answer/a1341387), [LinkedIn news](https://news.linkedin.com/2025/LinkedInWinsLegalBattleToProtectMemberData)). A tracker reports that Indeed prohibits automating Indeed Apply, which is not verified against Indeed's own text ([ConductAtlas](https://conductatlas.com/platform/indeed/indeed-terms-of-service/provision/CA-P-028259/automation-of-indeed-apply-process-prohibited/)). The Meta v. Bright Data contract ruling covered logged-off scraping and does not protect logged-in users who accepted the terms. Naukri's, Workday's, Greenhouse's and Lever's terms were not retrieved. The notes' reasoned position is that a user-operated extension pre-filling a form the user is viewing sits closest to a password manager, while a server bot logging in or submitting at scale resembles the automation platforms sue over. For launch, that means no on-site automation of LinkedIn, Indeed or Naukri, and employer-hosted ATS pages (Greenhouse, Lever, Ashby, Workday, Zoho Recruit and Indian ATSs) after a ToS read. It also means no CAPTCHA solving, proxy rotation or stealth: pause, highlight, and let the user solve it.

Three compliance points shape the build. Chrome Web Store policies took effect 1 Aug 2026 and tighten disclosure, require data collection to be necessary for a single disclosed purpose, and ban extensions designed to circumvent AI services' guardrails ([Chrome blog](https://developer.chrome.com/blog/cws-policy-updates-2026), surfaced by search and not opened). The practical response is a narrowly worded single purpose, activeTab plus optional per-ATS host permissions, no `debugger` permission, and LLM output treated strictly as data. The DPDP Rules, notified in Nov 2025 with sources differing on 13 versus 14 Nov, bring core fiduciary duties around **13 May 2027**, so they are not yet in force but should be designed for now. NIM and Anthropic need processor agreements and disclosure ([Deccan Herald](https://www.deccanherald.com/amp/story/india%2Fcentre-notifies-dpdp-rules-implementation-planned-in-phases-spread-over-12-18-months-3798465), [JSA Prism](https://www.jsalaw.com/?p=55573)). India's dark-pattern enforcement is active in 2026: McAfee was fined Rs 1 lakh over a renewal prompt, per a secondary summary, so one-click cancel and clear INR-with-GST pricing are table stakes ([Mondaq](https://www.mondaq.com/ccpas-guidelines-on-dark-patterns-an-overview/1844140)).

## India fit favours an adapter-led build

Existing Indian options in the notes are small and aimed at Naukri and LinkedIn auto-apply, which is the ToS-risky lane: ApplyAI Pro, ApplyIn5, Fillix, Arya by Mentoria and BlinkJob.ai, with unverified claims and no INR or UPI pricing evidence ([Stork](https://www.stork.ai/en/applyai-pro), [AlternativeTo](https://alternativeto.net/software/applyin5/about), [The Week](https://www.theweek.in/wire-updates/business/2025/11/12/dcm17-blinkjob.ai.html)). The only Naukri AI launch found is recruiter-side ([YourStory](https://yourstory.com/2026/07/naukri-launches-ai-recruitment-platform-india)). Global tools priced at roughly $15-40/month, about Rs 1,300-3,500, are expensive for freshers. That gap is plausible but not proven; it needs user research. The research did not cover Internshala, apna, Instahyre, foundit, campus-placement forms or Hindi UX, and these are gaps rather than findings. No cloud browser vendor lists an India region (Browserbase offers Singapore), and Chrome's built-in Gemini Nano needs about 22 GB free disk and a capable GPU or 16 GB RAM, so it is unsuitable as a primary path on budget laptops. Chrome's own Gemini autofill was Canary-only in July 2026 and may erode generic-field value, but not India-specific fields such as notice period, current/expected CTC in LPA, CGPA/percentage formats and category/PwD handling ([Android Authority](https://androidauthority.com/find-and-fill-with-gemini-3689348)). The ATS notes suggest adapter priority of Greenhouse, Lever, Workday (stable `data-automation-id` attributes per a Nexthink guide), Ashby, then Zoho Recruit, Keka and Darwinbox. India ATS market-share data came only from vendor blogs, so validate the order with the placement and job-posting data ApplyScout already holds.

## Ranked recommendation and verdict

1. **Extend the in-house MV3 filler (build).** Pipeline: content script collects field descriptors (label, name, aria, autocomplete, options); ATS adapters and a synonym/embedding mapper plus the answer bank fill known fields; only unmapped fields go to the backend LLM as compact JSON, with constrained-choice output and confidence thresholds; fill via native setters and dispatched events with ARIA-aware comboboxes; mark each field "from your profile / needs your input / skipped"; EEO, disability, caste/category and religion fields are detected by schema flags and keyword classifier and left for the user; the Submit and Next controls are never touched. This is the notes' synthesis, not a tested design.
2. **Borrow Page Agent's DOM-distillation ideas, and optionally vendor the module (MIT, with notice).** Use it for the unknown-ATS fallback only, behind a hard action allow-list. Study Stagehand's observe-returns-selector pattern. Nanobrowser is a fork-only reference.
3. **Stagehand or Browser Use (MIT) plus local Playwright, with Browserbase optional, as a nightly regression harness** on synthetic profiles and staged ATS pages. This is the best use of server-side agents.
4. **Do not buy, embed or resell Simplify, Careerflow or similar.** No API exists in the evidence, though absence of evidence is not proof. Buy a Simplify and a Careerflow subscription for competitor benchmarking.
5. **Avoid:** Skyvern in the product path, WebBrain code, Claude in Chrome as a dependency, autonomous auto-apply, unified ATS APIs, and any LinkedIn, Indeed or Naukri on-site automation.

## Two-week test plan

**Days 1-2: setup.** Build a fixture corpus of about 40 real application forms, about 8 each for Greenhouse, Lever, Workday, Ashby and a mix of Zoho Recruit, Keka, Darwinbox and iCIMS, plus 5 Indian campus or Google-Form-style forms. Create 6 synthetic Indian profiles spanning fresher to six years, including gaps, a notice period, a CTC and a CGPA. Define ground truth per field: expected value, or "must stay blank" for EEO and unknown facts. Run a ToS read for each target ATS, and have counsel confirm the licence and ToS questions in the legal notes.

**Days 3-6: baseline.** Measure ApplyScout's current filler per ATS: fields correctly filled, wrongly filled, left blank, and wrongly filled but looking plausible. Count required-field failures and file uploads. In parallel, install Simplify and Careerflow and run the same 40 forms by hand for comparison. Record the vendor-claimed rates (about 90% Greenhouse, 70% Workday) as the targets to beat.

**Days 7-9: LLM residual path.** Add the constrained-choice endpoint on NIM and on Claude. Compare the two on the unmapped fields for accuracy, abstain rate, latency, and cost per form (the number missing from all sources). Include the **fabrication probes**: forms asking for facts absent from the profile (work authorization, years in a specific tool, a certification). The pass condition is zero invented values; the model must abstain. Add **prompt-injection probes** with hidden text in job descriptions and field labels, expecting zero actions outside the enum.

**Days 10-11: Page Agent spike.** Wire Page Agent (pinned version, allow-list blocking submit, next and navigation) as the unknown-ATS fallback on 10 custom career pages. Compare it with the in-house path on success rate, steps and tokens, and inspect the manifest and permissions it implies.

**Days 12-13: harness and review.** Run Stagehand or Browser Use against the staged fixtures on a local browser to confirm it can serve as the nightly regression. Dry-run the Chrome Web Store checklist: single-purpose text, permission justification, privacy tab listing NIM and Anthropic.

**Day 14: decision.** Go if the in-house path reaches a pre-agreed bar (suggested, not sourced: at least 85% of fields correct or correctly flagged on Greenhouse, Lever and Ashby, at least 70% on Workday), has zero fabricated values and zero EEO auto-answers across all runs, and has LLM cost below a set ceiling per form. If Workday or the Indian ATSs miss the bar, prioritise their adapters rather than moving to an agent.

## What to re-check before committing

Re-open the following from an environment with working network access. First, every price: Browserbase, Browser Use cloud (reconcile $0.02/hr against $0.06/hr), Skyvern, Steel, Simplify (the $39.99 figure is from a competitor), Careerflow, JobCopilot (conflicting estimates) and AgentQL. Second, the Chrome Web Store listings (ratings, users, last-updated) for Simplify, Careerflow, Nanobrowser, Page Agent and the Indian tools, since none were reachable. Third, year and date of the Page Agent, Nanobrowser, Stagehand and Browser Use releases, because the pages omit the year. Fourth, the Playwright MCP licence, AgentQL licence (a directory claim only) and Page Agent/Nanobrowser manifest permissions. Fifth, the primary policy texts: Chrome Web Store policy updates and MV3 remote-code rules, LinkedIn s.8.2, Indeed's terms, Naukri/Info Edge terms, and Workday/Greenhouse/Lever terms. Sixth, the DPDP gazette dates and penalty schedule. Seventh, the AIHawk licence, left unresolved because the fetched repo contradicted the third-party listing. Eighth, Greenhouse's reCAPTCHA claim and Ashby's official docs. Finally, the notes disagree with each other on several points and the report has not picked sides: the HAL 42% versus Yutori 97% Online-Mind2Web boards, the two WebChoreArena figures (44.9% and 54.8%), the Browser Use cloud hourly rate, and the free-tier size for AgentQL.

## Conclusion

The research changes the question from "which agent do we adopt" to "how much agent do we need at all." A form filler that never clicks Submit does not need browsing autonomy, which is the capability that carries the credential, anti-bot, ToS and COGS risks in server-side agents and the failure rates in the benchmarks. What it needs is trustworthy field typing, per-ATS adapters, provenance for every value and a model that can say "I don't know." Those are properties ApplyScout already controls, and they are also the differentiators against Simplify-style tools: honest per-ATS fill rates, India-specific fields, and INR pricing with clean cancellation.

The decision is time-sensitive in one respect only. The compliance window is open: DPDP duties are expected around May 2027, and the Chrome Web Store rules took effect on 1 Aug 2026. Designing consent, processor agreements and a narrow single purpose into the extension now costs little, while retrofitting them after launch is expensive. The largest unknown is not technical but evidential. No one has published a Workday, Greenhouse or Lever agent benchmark, so ApplyScout's own two-week fixture results will be the first reliable number in the room, and worth publishing.
